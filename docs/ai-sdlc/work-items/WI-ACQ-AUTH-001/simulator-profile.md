# Operation A — proposed simulator detail register (r3)

Status: SIMULATOR DESIGN ASSUMPTIONS / PROPOSED, pending Fernando's disposition. These are not scheme rules, human approvals, architecture decisions or a replacement for requirements.md. HD-01–HD-03 remain authoritative; source concepts are Guide §§1,4.2,5–6,11. References P01–P08 identify eight proposal groups, not eight approved rules.

| ID | Concrete proposed detail | Authority boundary |
| :-- | :-- | :-- |
| P01 | Symbolic credential ranges SIM-APP-000–SIM-APP-999 approve; SIM-DEC-000–SIM-DEC-999 decline; SIM-TMO-000–SIM-TMO-999 do not confirm before timeout. Registered fixtures only; each has exactly one permitted named route; unknown fixture rejects before dispatch. | HD-01 approves decision classes and named routes, not these labels or one-route mapping. Labels are never real BINs/PANs. |
| P02 | Amount at most two fractional digits; no rounding. Entry mode simulated-contact or simulated-contactless; CVM simulated-verified or simulated-not-required; cryptogram-present required boolean, either value allowed, without cryptographic validation. Synthetic risk pass/reject, omitted defaults pass; reject prevents dispatch. Required channel exchange reference for correlation. | HD-01 approves USD 1.00–9,999.99 and three synthetic CP indicators; exact enums/precision/risk/requiredness are proposed r2 details. |
| P03 | Compare resolved amount, currency, credential, terminal, channel, entry mode, CVM, cryptogram flag and risk; exchange/prior-attempt references are excluded. Defaults resolve before comparison. | HD-02 approves conflict rejection; equality field set is proposed. No wire normalization is selected. |
| P04 | Authenticate and authorize context first; reject failed mandatory validation without dispatch. If a prior reference is supplied, validate its existence and authorized acquirer/merchant access before returning any replay evidence. Missing, malformed, unknown or foreign link rejects generically without foreign outcome/reference disclosure, even if a local key matches. Valid prior link must identify the same business key and identical resolved payment data; changed data/key rejects as conflict, no dispatch, no original mutation. | Conservative proposed ordering and valid-retry definition; HD-02 supplies invalid/foreign rejection and no-redispatch core. An absent optional link is not itself an invalid link; unlinked requests use key lookup. |
| P05 | After P04, an identical retained key is replayed with original reference and latest evidence, never dispatched again. A valid linked retry does the same. If original is still in flight, return not-confirmed (pending), not a final decline; do not wait for a second issuer decision or create a second dispatch. Concurrent first arrivals of identical key/data produce one business authorization and at most one dispatch; a conflicting concurrent repeat rejects. | HD-02 approved replay/no-redispatch core; concurrency and immediate pending response are proposed semantics, no locking or component design. |
| P06 | Duplicate window starts at first receipt: [t0,t0+24 h). At exact end an unlinked request is evaluated as new, subject to normal checks; no implicit claim that the earlier payment was cancelled. Explicit linked requests are never made new by expiry: resolve retained authorized link and apply P04/P05, or reject unavailable/invalid reference without dispatch. Proposed retain prior links/evidence for the exercise under P08; expiry is not deletion. A changed channel payment reference is new only when unlinked. | HD-02 approves 24 h default, not boundary/new-payment/retention details. Intentional new purchases after unknown should not be disguised as safe retries. |
| P07 | Evaluate against latest valid correlated evidence recorded when the outcome is determined. Confirmation available at that instant, including at the timeout boundary, takes precedence over timeout, ambiguity or malformed response. Without it, timeout at default 30 s from dispatch or ambiguous/malformed reply yields not-confirmed. Malformed includes missing decision, unrecognized decision, wrong correlation or contradictory content; transport receipt is not issuer evidence. Later valid correlated issuer confirmation updates current result, preserving previous uncertainty and original reference. A delayed timer/ambiguous message never regresses confirmed to unknown. Incompatible later confirmations are retained as conflicting evidence and flagged internally; they do not silently replace an established decision. No unsolicited notification, reversal, inquiry or redispatch. | Guide §5 sources ambiguity-as-unknown; HD-02 approves late evidence/latest retry. 30 s is an adjustable default permitted by HD-02, not newly human-selected. Evaluation/correlation/conflicting-evidence semantics are proposed. |
| P08 | Return authorized business outcome and transaction reference, not whole history. Keep internal decision source, reasons, route, correlations and synthetic request/response evidence restricted to authorized operators, masking credential details outside necessary test identifiers. Preserve evidence and resolvable prior links for the simulator exercise; no automatic purge is specified. Obtain owner/security policy before interface construction for exact fields, masks, access and eventual retention/purge. | Guide §6 requires internal auditability, not caller-visible reasons. Duplicate window is not audit retention. This is a concrete proposed boundary; exact policy remains UNRESOLVED. |

No permitted route: processor rejection before dispatch (R03/R18), not issuer decline or downstream unknown. Routing cannot fall back to a foreign acquirer's route/credentials. This follows sourced mandate/routing controls; the exact fixture mapping is P01.

Business evaluation order P04 → P05/P06 → eligible new dispatch; P07 governs result evidence throughout. Failed current caller eligibility never reveals a stored result. Replays do not re-run downstream decisions or revise original payment data. These are observable rules, not a mandated technical synchronization/state-machine design.
