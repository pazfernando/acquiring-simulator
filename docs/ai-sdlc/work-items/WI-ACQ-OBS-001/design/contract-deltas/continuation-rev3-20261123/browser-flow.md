# Proposed auxiliary-context flow — DR2-01 / N-01
DRAFT DESIGN ASSUMPTION, not human approval or issuer/browser proof. Overrides every same-window/top-level-redirect interpretation in this composed packet, including inherited D2/D5, K1-01/02 and W20. No other obligation is dropped.

1. The original HTTPS SPA owns both resource tokens, all pending flow records and all verifiers in runtime memory only. Start HTTP login from a user gesture by opening a fresh unnamed auxiliary top-level window; retain its exact WindowProxy. Navigate that child, never the SPA, to the pinned issuer authorize URL. No iframe, hidden broker, backend token custody or combined token.
2. Before navigation generate independent cryptographically random state, nonce and PKCE verifier (S256) for EACH attempt/resource, including an interactive replacement after login_required. Bind memory record to exact child reference, exact callback origin/path, issuer, public client, expected resource, redirect_uri, SPA session epoch and proposed 120-second deadline. Serialize flows; no concurrent reuse of a child. No state/verifier/nonce/token in localStorage, sessionStorage, cookie, IndexedDB, Cache API, service worker, window.name, HTML or logs. Authorize query necessarily contains state/nonce/challenge only; never verifier/bearer. Issuer SSO cookies remain issuer-only, not API credentials.
3. The child returns to the exact same-origin static /auth/callback with authorization code/state/issuer response or error. Callback code has no token custody, analytics or third-party runtime. It copies response in memory, immediately history.replaceState to the clean path, and postMessage to its opener using the exact configured SPA origin, never '*'. Callback must reject absent opener; never recover through persistent storage or broadcast channels. Code/error query must be excluded from access logs/referrers and caches; callback no-store/no-referrer and CSP apply on success/error. Infrastructure proof remains outstanding.
4. Parent accepts only event.origin exactly equal to configured callback origin AND event.source === the retained WindowProxy AND the exact closed message schema/type. Require active unexpired epoch, issuer and state matching the sole pending resource flow; reject absent/duplicate params, unknown errors, unexpected payload and unsolicited child. Source/origin alone is insufficient. Atomically consume pending state before async exchange; replay cannot start a second exchange. Parent exchanges code directly with issuer using its memory-only verifier and exact redirect_uri; child never receives verifier or bearer. Validate issuer metadata, signature/algorithm/kid, ID-token nonce/aud/azp/issuer/time and access-token resource rules before installation. Missing nonce or wrong token resource rejects. Never treat ID token as resource token.
5. On HTTP success retain HTTP token in original SPA memory; start separate WS flow in a fresh child with new state/nonce/verifier and prompt=none. login_required retires/clears that flow; show a user action to open a fresh interactive flow for ws.observe only. No automatic purchase action or queued form submission. WS success installs only disjoint WS token in original SPA memory; prove HTTP history and WS coexist without SPA navigation.
6. Close child and erase code/verifier/nonce/flow after success, error, closure, timeout or cancellation. A failed WS flow grants no WS authority and does not extend HTTP validity. HTTP failure creates no session. Invalid callback grants nothing; reject and retire that pending flow. Existing valid HTTP token can remain until its own expiry/current-mandate failure; UI reports observation disconnected. HTTP expiry/logout/SPA reload/unload clears both tokens and pending flows, closes WS and children; browser Back/bfcache restoration forces fresh login rather than resurrecting authority. WS expiry clears WS and closes its epoch; reauthentication creates NEW epoch/snapshot, never cursor transplant. Logout also attempts issuer logout; network failure is shown, not a claim of revocation.
7. Popup blocker, null/closed/severed opener, deadline expiry or COOP isolation failure => no token accepted, explicit authentication unavailable, zero payment POST. A user can retry a fresh flow; no same-window or persisted-bearer fallback. Original SPA token expiry remains enforced while child login waits.

## Opener/COOP feasibility gate
Proposed SPA/callback COOP is same-origin-allow-popups (not noopener); open without noopener/noreferrer that would sever the required reference, using no-referrer response policy instead. Issuer navigation and redirects must preserve the opener relationship in each target browser. An issuer COOP same-origin or incompatible browsing-context group can sever it irreversibly: matching callback origin alone does not repair this. Do not weaken issuer headers silently. Record effective COOP/COEP/CSP headers on SPA, callback, issuer and all redirect legs plus actual WindowProxy/message behavior, popup blocking, logout, reload/bfcache and interactive login_required. CSP must allow issuer fetch under exact CORS and never scripts from issuer. No cross-origin isolation claim. This is conditional feasibility, not a verified header prescription. If pinned issuer/stack/browser fails, stop integrated K1 and return concrete reviewed architectural alternative to the coordinator for human disposition. No broker, combined token or HTTP-only substitution is selected.

## Required real browser negatives
Wrong origin; same origin/wrong source window; right child/wrong state; stale epoch; expired flow; missing/wrong/reused nonce; wrong verifier; code reuse; extra/duplicate callback parameters; callback after parent reload; child closure; popup denied; severed opener; unsolicited success/error; refresh token unexpectedly returned (discard, report). For each assert token installs=0, financial sends=0, claims=0 and automaticPaymentPosts=0. Browser trace must prove original SPA remains alive across both issuer navigations and storage/log inspection finds no bearer/verifier. Documentary fixtures are not execution.
