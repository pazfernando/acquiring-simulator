# Observation and architecture contract — PROPOSED
DESIGN ASSUMPTIONS throughout; not architecture approval or security certification.

## O1 — common hook activation
Every present/future implemented capability MUST declare versioned task manifest and emit this schema through common instrumentation before activation. Missing manifest/hook disables activation, not reason to implement future operations. Initial A manifest: receive, context-check, validate, idempotency-check, request-adapt, dispatch, response-adapt, business-persist, channel-response; network-forward and issuer-decide only where actually instrumented/authorized. Each manifest declares required producers, conditional branches and terminal outcomes. No ISO mapping required for auxiliary tasks.
Event JSON <=2048 UTF-8 bytes, only allowlisted ASCII scalar data. Required: schemaVersion=1, eventId (producer-scoped immutable 1–64), producerId/instanceId (1–64), actor (CHANNEL/ACL/PROCESSOR/NETWORK/ISSUER), capability/version (1–32), manifestVersion (1–32), acquirerRef/merchantRef/terminalRef (1–128), transactionId/operationId/attemptId/correlationId/taskExecutionId (1–64), taskName (manifest enum), status (STARTED/SUCCEEDED/FAILED/SKIPPED), occurredAt/collectedAt (RFC3339 UTC), producerSequence (nonnegative integer), provenance (OBSERVED/INFERRED), reason (allowlisted enum).
Optional parentTaskId/parentEventId/retryOfAttemptId/originalOperationId (1–64), startedAt/endedAt (UTC), elapsedMicros (nonnegative integer), clockQuality (SAME_MONOTONIC/SKEWED/UNKNOWN), evidenceRef (safe authorized journal reference, never payload), gapCode (MISSING_START/MISSING_TERMINAL/MISSING_PRODUCER/PERSISTENCE_LOSS/CONFLICT).
Collector supplies collectedAt, ingestion sequence and validated context (never silently replaced); reject forged context/producer. Missing IDs before authentication use a restricted admission record/attempt, not foreign transaction attachment. No arbitrary labels/free-form stack traces. No bodies, JWTs, PAN, PIN, EMV/3DS blobs, credential values or raw wire in traces/logs, even on parse failure. Fixture ID only where separately allowlisted; redact before persistence. Render text inert.

## O2 — evidence, timing and duplicate semantics
Task execution ID identifies one execution, attempt identifies submission, event identity identifies delivery-deduplicated fact. Dedupe key (producerId,eventId), compare canonical content excluding collector fields. Exact duplicates no-op; same ID different content quarantines original/new safe metadata and opens integrity gap. Missing terminal never implies FAILED. Reordered terminal/start retained with causal links; duration only same-clock monotonic measurement, never subtract remote wall clocks. Maintain occurred/collected times and journal business version independently of ingestion order.
Business outcome (including UNKNOWN), observation completeness (COMPLETE/PARTIAL/UNKNOWN as-of manifest/watermark), and server freshness (CURRENT/STALE/UNKNOWN) and client connection (CONNECTED/DISCONNECTED/UNKNOWN) are independent. COMPLETE means observed required task evidence as-of watermark, not payment finality. Unknown/uninstrumented producer remains gap. Events are not business evidence; businessVersion comes from authorized journal.

## O3 — admission and failure policy
Recommend fail-closed durable trace admission before any possibly-effectful dispatch: conditional business claim + dispatch intent durably committed, then durable sanitized trace-admission record, then dispatch. If either admission fails, do not initiate dispatch. Only positively unsent proof permits NOT_DISPATCHED; ambiguous/unreadable commit follows C3 UNAVAILABLE, never assume no-send. Do not create fake issuer decline. A claimed but undispatched instruction remains reserved/not-dispatched: identical retry reads it, no automatic redispatch. Cross-store partial failure may leave orphan admission record, reconciled administratively without payment execution.
Write business dispatch-intent before invocation. From possible send onward, inability to prove non-delivery means UNKNOWN. No automatic SDK/HTTP retry, rollback, reversal or new instruction due to trace failure.
Trace append failure after possible dispatch: preserve authoritative journal outcome if durably committed, mark PARTIAL/PERSISTENCE_LOSS. Business result remains known even if trace incomplete. Use durable outbox attached to business journal for recoverable sanitized notifications (max 100 pending entries per operation, 24h replay); admission/backpressure rejects NEW work before dispatch on capacity exhaustion. Retrying outbox delivery never dispatches payment. No guarantee for observations never durably written; gap is explicit and cannot be invented away.
Business-journal failure: before claim/send no dispatch. After possible dispatch, a verified reply in volatile memory or trace is NOT durable business confirmation. For this invocation independently knowing possible send, return C3 503 NOT_CONFIRMED/PENDING when business evidence commit is unavailable; for unreadable restart/history with no such knowledge use null/UNAVAILABLE. Retain readable durable confirmation or a committed version read earlier in this invocation, not an unverified client snapshot. Persist gap where possible. Verified reply may be committed later through authorized evidence processing; no trace event or issuer table is promoted to journal truth. Distinguish traceUnavailable from businessJournalUnavailable internally. Neither HTTP failure nor green task means decline/approval. If all stores unavailable expose UNKNOWN observation/serverFreshness; no promise of reconstructed lost events.

## O4 — concrete architecture recommendation, not approval
Use short polling rather than SSE/WebSocket for initial low-cost API Gateway HTTP API + Lambda baseline. GET /console/v1/transactions?cursor=... and /transactions/{id}, /transactions/{id}/events?cursor=...; no payment dispatch on reads. Active view polls each 1 second; hidden/offline views pause and declare stale. Backoff to 5/10/30 seconds on observation failure, never repeat POST. Request timeout 1 second for healthy observation target; for NEW events collected during an already connected healthy session, collection→display p95 <=2s and p99 <=5s at 100 active transactions/1000 retained events, measured independently from payment deadline. Server freshness STALE after 5s without successful collection watermark, UNKNOWN when stores cannot establish watermark. Browser separately marks DISCONNECTED on known offline/transport failure, CONNECTED on successful response, UNKNOWN before first contact.
DynamoDB on-demand dedicated trace table: partition acq+mid+transactionId, sort key collector monotonic sequence/event identity; conditional event dedupe. Context list index partition acq+mid, sort firstReceipt+transactionId. No global tenant-readable scan or issuer cross-table join. History snapshot watermark and last evaluated key bound each page; new appends fetched after watermark in next poll. Default/max page 100 events, max replay 1000 events or 1 MiB per reconnect; beyond that return 410 RESYNC_REQUIRED and paged snapshot, preserve explicit historical gap. Recovery <=10s for 100 transactions/1000 events under healthy services. Signed opaque cursor binds subject/context/filter/watermark, expires 15 minutes, cannot authorize access itself. Invalid/tampered cursor 400; expired 410. Never silently skip a page.
Permissions: submit requires console:submit plus active full context; list/detail/poll/replay console:read plus same context; issuer diagnostic requires diagnostics:issuer in addition to context and read. Issuer-only table inaccessible to processor role. Server reauthorizes every GET/poll/page; no cache-only authorization. Revocation/context switch clears client records and cancels old requests; server denies next request, no stale-context merge. Already seen data cannot be remotely recalled. Separate service roles/least privilege, encrypted storage/transport; independent Security review required.
Retain trace events seven days from collectedAt; filter reads at expiry even if DynamoDB TTL physical deletion lags (target physical deletion <=48h after expiry, alert on lag). Trace deletion removes related indexes and safe trace quarantine, not business journal, alias maps, idempotency generations, evidence or prior links. Business retention remains existing exercise retention with no automatic purge; seven days is NOT business reference retention and NOT inherited CloudWatch policy. No raw trace archive/export. Retention-expired detail reports trace unavailable while preserving authorized business result/references.

## O2a — exact canonical identity and restart policy
Dedupe identity=(environment-bound registered producerId,eventId). ProducerId is stable across instance restart, cannot be chosen from event body; instanceId is a boot identifier. EventId is durably allocated unique within producerId (or persisted outbox ID), never restarted counter without persistent epoch. Retransmission preserves original instanceId and all original event fields, even when delivered by a new instance.
Canonical content is RFC8785 JSON of these exact keys: schemaVersion,eventId,producerId,instanceId,actor,capability,version,manifestVersion,acquirerRef,merchantRef,terminalRef,transactionId,operationId,attemptId,correlationId,taskExecutionId,taskName,status,occurredAt,producerSequence,provenance,reason,parentTaskId,parentEventId,retryOfAttemptId,originalOperationId,startedAt,endedAt,elapsedMicros,clockQuality,evidenceRef,gapCode. Optional absent values normalize to null. Exclude ONLY collectedAt, ingestionSequence and collectorReceiptId; collector generates those. Reject all undeclared keys. Producer-supplied collectedAt is forbidden on ingress (collector adds it on stored/read envelope). Validate producer authority and asserted original context BEFORE dedupe; forged context is rejection, never reassigned to authorized context. Same canonical payload with different collector time is exact replay; changed status/instance/context/occurrence or optional content is conflict, except forged context fails authorization first.

## O3a — durable send states and crash/restart contract
| Durable state | Meaning | Initial / replay / restart behavior |
| --- | --- | --- |
| no claim | no accepted business operation | failure before claim: 503 null outcome NOT_DISPATCHED only for unambiguously unclaimed NEW work with no prior possible send and positive current-invocation non-send proof; storage-unreadable restart: UNAVAILABLE, never infer no-send |
| CLAIMED_NOT_SENT | claim committed; no invocation permitted yet | 503 null outcome NOT_DISPATCHED on trace-admission failure or any read-only retry; keep original IDs, link new attempt, no automatic send |
| POSSIBLE_SEND | CAS transition committed after trace admission and before invoking transport | 202 NOT_CONFIRMED PENDING while active/replayed; deadline 200 NOT_CONFIRMED; restart never resumes invocation, even if crash actually preceded send |
| CONFIRMED | durable P5 evidence+business version committed | retain known APPROVED/DECLINED/PROCESSOR_REJECTED on replay/restart, never regress |
Trace admission success alone cannot send: CAS CLAIMED_NOT_SENT→POSSIBLE_SEND must durably succeed first. Crash before CAS leaves provably unsent; after CAS but before invocation is deliberately ambiguous. Crash after invocation/before receipt admission remains POSSIBLE_SEND. Crash after durable evidence before trace append retains CONFIRMED. If CAS write outcome is ambiguous, query authoritative journal; if not readable no invocation, return UNAVAILABLE and no assertion of NOT_DISPATCHED. Retry never performs CAS/send on an old reservation. Administrative resolution is separately authorized, not a new endpoint here.
Unlinked request at exact 24h boundary may create a new generation even for old CLAIMED_NOT_SENT/POSSIBLE_SEND. Show warning: 'New generation is a new authorization, not recovery; the earlier reservation/outcome is retained and not cancelled.' Explicit prior always resolves original after expiry or rejects; never creates new generation. Reads/restart/reconnect do not expire into new payments by themselves.
Backlog recovery measurement starts on successful authorized reconnect, ends at displayed snapshot watermark, <=10s for stated bound. Old retained events keep original collection timestamps and backlog age label; they are NOT included in connected-live latency percentiles. All-store failure returns safe 503 UNAVAILABLE without body-derived payment evidence; last client snapshot marked stale/unknown with its asOf, not silently current.
