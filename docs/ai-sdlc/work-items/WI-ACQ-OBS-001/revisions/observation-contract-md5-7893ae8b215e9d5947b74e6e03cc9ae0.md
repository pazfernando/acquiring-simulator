# Observation and architecture contract — PROPOSED
DESIGN ASSUMPTIONS throughout; not architecture approval or security certification.

## O1 — common hook activation
Every present/future implemented capability MUST declare versioned task manifest and emit this schema through common instrumentation before activation. Missing manifest/hook disables activation, not reason to implement future operations. Initial A manifest: receive, context-check, validate, idempotency-check, request-adapt, dispatch, response-adapt, business-persist, channel-response; network-forward and issuer-decide only where actually instrumented/authorized. Each manifest declares required producers, conditional branches and terminal outcomes. No ISO mapping required for auxiliary tasks.
Event JSON <=2048 UTF-8 bytes, only allowlisted ASCII scalar data. Required: schemaVersion=1, eventId (producer-scoped immutable 1–64), producerId/instanceId (1–64), actor (CHANNEL/ACL/PROCESSOR/NETWORK/ISSUER), capability/version (1–32), manifestVersion (1–32), acquirerRef/merchantRef/terminalRef (1–128), transactionId/operationId/attemptId/correlationId/taskExecutionId (1–64), taskName (manifest enum), status (STARTED/SUCCEEDED/FAILED/SKIPPED), occurredAt/collectedAt (RFC3339 UTC), producerSequence (nonnegative integer), provenance (OBSERVED/INFERRED), reason (allowlisted enum).
Optional parentTaskId/parentEventId/retryOfAttemptId/originalOperationId (1–64), startedAt/endedAt (UTC), elapsedMicros (nonnegative integer), clockQuality (SAME_MONOTONIC/SKEWED/UNKNOWN), evidenceRef (safe authorized journal reference, never payload), gapCode (MISSING_START/MISSING_TERMINAL/MISSING_PRODUCER/PERSISTENCE_LOSS/CONFLICT).
Collector supplies collectedAt, ingestion sequence and authorization-derived context; reject forged context/producer. Missing IDs before authentication use a restricted admission record/attempt, not foreign transaction attachment. No arbitrary labels/free-form stack traces. No bodies, JWTs, PAN, PIN, EMV/3DS blobs, credential values or raw wire in traces/logs, even on parse failure. Fixture ID only where separately allowlisted; redact before persistence. Render text inert.

## O2 — evidence, timing and duplicate semantics
Task execution ID identifies one execution, attempt identifies submission, event identity identifies delivery-deduplicated fact. Dedupe key (producerId,eventId), compare canonical content excluding collector fields. Exact duplicates no-op; same ID different content quarantines original/new safe metadata and opens integrity gap. Missing terminal never implies FAILED. Reordered terminal/start retained with causal links; duration only same-clock monotonic measurement, never subtract remote wall clocks. Maintain occurred/collected times and journal business version independently of ingestion order.
Business outcome (including UNKNOWN), observation completeness (COMPLETE/PARTIAL/UNKNOWN as-of manifest/watermark), and connection freshness (CURRENT/STALE/DISCONNECTED) are independent. COMPLETE means observed required task evidence as-of watermark, not payment finality. Unknown/uninstrumented producer remains gap. Events are not business evidence; businessVersion comes from authorized journal.

## O3 — admission and failure policy
Recommend fail-closed durable trace admission before any possibly-effectful dispatch: conditional business claim + dispatch intent durably committed, then durable sanitized trace-admission record, then dispatch. If either durable admission fails, no dispatch; return 503 NOT_DISPATCHED, do not create fake issuer decline. A claimed but undispatched instruction remains reserved/not-dispatched: identical retry reads it, no automatic redispatch. Cross-store partial failure may leave orphan admission record, reconciled administratively without payment execution.
Write business dispatch-intent before invocation. From possible send onward, inability to prove non-delivery means UNKNOWN. No automatic SDK/HTTP retry, rollback, reversal or new instruction due to trace failure.
Trace append failure after possible dispatch: preserve authoritative journal outcome if durably committed, mark PARTIAL/PERSISTENCE_LOSS. Business result remains known even if trace incomplete. Use durable outbox attached to business journal for recoverable sanitized notifications (max 100 pending entries per operation, 24h replay); admission/backpressure rejects NEW work before dispatch on capacity exhaustion. Retrying outbox delivery never dispatches payment. No guarantee for observations never durably written; gap is explicit and cannot be invented away.
Business-journal failure: before claim/send no dispatch. After possible dispatch, a verified reply in volatile memory or trace is NOT durable business confirmation. Return 503 with NOT_CONFIRMED when durable business evidence unavailable, persist gap where possible; if prior durable confirmation exists retain it. Verified reply may be committed later through authorized evidence processing; no trace event or issuer table is promoted to journal truth. Distinguish traceUnavailable from businessJournalUnavailable internally. Neither HTTP failure nor green task means decline/approval. If all stores unavailable expose UNKNOWN observation/freshness; no promise of reconstructed lost events.

## O4 — concrete architecture recommendation, not approval
Use short polling rather than SSE/WebSocket for initial low-cost API Gateway HTTP API + Lambda baseline. GET /console/v1/transactions?cursor=... and /transactions/{id}, /transactions/{id}/events?cursor=...; no payment dispatch on reads. Active view polls each 1 second; hidden/offline views pause and declare stale. Backoff to 5/10/30 seconds on observation failure, never repeat POST. Request timeout 1 second for healthy observation target; collection→display p95 <=2s and p99 <=5s at 100 active transactions/1000 retained events, measured independently from payment deadline. Stale after 5s without successful watermark, disconnected on known offline.
DynamoDB on-demand dedicated trace table: partition acq+mid+transactionId, sort key collector monotonic sequence/event identity; conditional event dedupe. Context list index partition acq+mid, sort firstReceipt+transactionId. No global tenant-readable scan or issuer cross-table join. History snapshot watermark and last evaluated key bound each page; new appends fetched after watermark in next poll. Default/max page 100 events, max replay 1000 events or 1 MiB per reconnect; beyond that return 410 RESYNC_REQUIRED and paged snapshot, preserve explicit historical gap. Recovery <=10s for 100 transactions/1000 events under healthy services. Signed opaque cursor binds subject/context/filter/watermark, expires 15 minutes, cannot authorize access itself. Invalid/tampered cursor 400; expired 410. Never silently skip a page.
Permissions: submit requires console:submit plus active full context; list/detail/poll/replay console:read plus same context; issuer diagnostic requires diagnostics:issuer in addition to context and read. Issuer-only table inaccessible to processor role. Server reauthorizes every GET/poll/page; no cache-only authorization. Revocation/context switch clears client records and cancels old requests; server denies next request, no stale-context merge. Already seen data cannot be remotely recalled. Separate service roles/least privilege, encrypted storage/transport; independent Security review required.
Retain trace events seven days from collectedAt; filter reads at expiry even if DynamoDB TTL physical deletion lags (target physical deletion <=48h after expiry, alert on lag). Trace deletion removes related indexes and safe trace quarantine, not business journal, alias maps, idempotency generations, evidence or prior links. Business retention remains existing exercise retention with no automatic purge; seven days is NOT business reference retention and NOT inherited CloudWatch policy. No raw trace archive/export. Retention-expired detail reports trace unavailable while preserving authorized business result/references.
