## Challenge of D2 semantics

| Condition | Required proposed behavior | Assessment |
| --- | --- | --- |
| New work cannot durably claim/admit trace | No send. NOT_DISPATCHED only with positive unsent proof; ambiguous/unreadable write is UNAVAILABLE. | Concrete, no fabricated issuer outcome. |
| Claim exists but trace admission fails | CLAIMED_NOT_SENT reservation retained; null outcome, original links; retry/restart does not resume send. | Availability cost explicitly disclosed. |
| CAS to POSSIBLE_SEND succeeds; crash before actual invocation | Treat as possible send; no resumed invocation, no false no-send assertion. | Conservative ambiguity is intentional, not a task failure becoming decline. |
| Send may have occurred; journal evidence commit fails | Current invocation returns NOT_CONFIRMED/PENDING with journal fault; unreadable later history returns null/UNAVAILABLE. | Distinct knowledge boundaries, same no-redispatch rule. |
| Confirmation durably committed/read, then trace/store fails | Retain known committed outcome/version and asOf; degrade trace/freshness independently. | No regression of financial evidence. |
| Issuer proof exists only remotely/in memory/in trace | Not processor confirmation until authenticated correlated P5 admission durably commits receipt/evidence/version. | Issuer truth and processor-known truth remain distinct. |
| Delayed valid proof | Normal and late use same authentication/binding/admission contract; reconcile original idempotently. | No public recovery endpoint/worker is silently commissioned. |
| Invalid/missing/oversized/untrusted proof after possible send | Reject candidate evidence, preserve readable known confirmation or uncertainty; never infer non-delivery. | New response hash strengthens byte binding without changing payment meaning. |
| Duplicate channel submission, outbox redelivery, GET/reconnect | Read/replay only; no new financial instruction. | Observation repair cannot resend authorization. |
| Unlinked request at retained 24h boundary | Only normal new-generation evaluation, explicit new-authorization warning; original not cancelled. Linked retry never becomes new. | Existing proposed expiry semantics preserved, not advertised as safe recovery. |

C3's read-first confirmation precedence applies after current access/schema/prior/conflict checks. It does not authorize cross-context replay or reveal foreign records. An invalid new attempt can be rejected without overwriting an existing confirmed operation. COMPLETED ends an exchange; NOT_CONFIRMED/COMPLETED does not claim financial finality.

Fail-closed policy deliberately allows unavailable tracing to prevent new work and can strand an unsent reservation pending separately authorized resolution. This trade-off is a legitimate simulator policy choice now fully visible to the owner. The team has not assumed fail-open buffering or automatic recovery. Outbox notification retries remain observations, not financial retries.
