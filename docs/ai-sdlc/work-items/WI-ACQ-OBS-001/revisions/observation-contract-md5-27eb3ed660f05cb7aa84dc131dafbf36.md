## O1 — common hook and honest coverage
Every implemented/future capability must supply the common hook and a versioned task manifest BEFORE activation, including auxiliary work without financial ISO mapping. No future operation is commissioned. Initial A manifest: receive, context-check, validate, idempotency-check, request-adapt, dispatch, response-adapt, business-persist, channel-response, plus network-forward/issuer-decide where actually instrumented. Manifest declares expected tasks/producers/conditional branches, event class and durability guarantee; inability to observe another actor is an explicit gap, not a fabricated execution.
Three classes:
1. CRITICAL_COMMITTED: safe notification of a real committed business transition, written atomically with that transition. Claim, possible-send, initial result (confirmed/rejected/unknown), later verified confirmation, first integrity-flag transition. These reconstruct business-transition history, NOT every task.
2. TASK_BEST_EFFORT: hook emits started/terminal observations without awaiting downstream telemetry/history acknowledgement. Bounded memory producer queues may lose data on crash/capacity; proposed local queue <=100 events or 200KiB per invocation, drop rather than delay payment at bound. Events may reach an authenticated asynchronous observation ingress/projector but are never required before send. No separate durable store admission is introduced. Every hook invocation is required; every hook delivery is NOT guaranteed durable.
3. TECHNICAL_SAMPLED: redacted OTel spans/metrics/logs; ADOT asynchronously exports to configured X-Ray/CloudWatch backends as appropriate, not necessarily all to CloudWatch. Sampling, dropped batches and Lambda lifecycle loss mean spans cannot prove functional coverage or payment evidence.
Pre-auth receive/start/validation errors before a business claim have no guaranteed durable transaction linkage. Use safe request/attempt IDs where known; an observer crash may leave no event. UI shows PRE_ADMISSION_UNOBSERVED/MISSING_START/MISSING_TERMINAL/MISSING_PRODUCER, never synthesizes FAILED. No global correlation lookup can disclose foreign or unauthenticated inputs. No assertion that every task is durably captured at zero synchronous cost. Proposed best-effort task transport: a background exporter uses IAM-scoped asynchronous Lambda Invoke of the SAME projector (deliveryClass=TASK_BEST_EFFORT), not another financial endpoint. Queue offer never waits for invocation acknowledgement on business thread; Lambda lifecycle/export worker loss remains possible. EventId survives any exporter redelivery. Proposed async event age1h/max2 retries and sanitized failure pointer require runtime/config preflight; these are not guarantees. Critical Streams events use the separate O6 validation path; a task envelope cannot masquerade as critical committed evidence. Business transactions/outbox add bounded latency/storage cost; async extension still consumes CPU/memory and may add lifecycle overhead.

## O1a — common event shape and source/privacy boundary
Event payload <=2048 ASCII/UTF-8 bytes; reject oversize/unknown fields before a critical transition is commissioned in its manifest. Required producer fields: schemaVersion=1,eventId (1–64),producerId/instanceId (1–64),actor (CHANNEL/ACL/PROCESSOR/NETWORK/ISSUER),capability/version/manifestVersion (1–32),acquirerRef/merchantRef/terminalRef (1–128),transactionId/operationId/attemptId/correlationId/taskExecutionId (1–64),taskName (manifest enum),status (STARTED/SUCCEEDED/FAILED/SKIPPED),occurredAt (UTC RFC3339),producerSequence (nonnegative integer),provenance (OBSERVED/INFERRED),reason (allowlisted enum).
Optional parentTaskId,parentEventId,retryOfAttemptId,originalOperationId (1–64),startedAt,endedAt,elapsedMicros,clockQuality (SAME_MONOTONIC/SKEWED/UNKNOWN),evidenceRef, gapCode. Missing IDs before authentication use a separate restricted admission observation, not invented transaction IDs. New transport wrapper (not canonical event content) declares deliveryClass=CRITICAL_COMMITTED/TASK_BEST_EFFORT/TECHNICAL_SAMPLED, eventSha256, journalVersion/operationSequence (critical only), committedAt (critical only), collectedAt, projectedAt, collectorReceiptId and ingestionSequence.
Critical payload context derives from authoritative business record; producer assertions must match authorization, never silently reassigned. Producer-supplied collectedAt on task ingress is forbidden; collector supplies it. For critical events collectedAt=committedAt retained from outbox, NOT delayed projection time; projectedAt records later materialization. Retain payload original across redelivery.
No bodies, JWTs, PAN, PIN, EMV/3DS values, credentials, raw ISO, proofs/signatures or free-form stack traces in event/outbox/history/telemetry/failure destinations, even on parsing error. Only allowlisted IDs/reasons and evidence references; mask identifiers outside authorized context. Source redaction precedes all exports; telemetry resource attributes must not bypass tenant isolation. Render text inert.

## O2 — projection truth and completeness
Business journal is authoritative. History is a versioned asynchronous read model; a history row with APPROVED is merely a projection of a journal version, never new issuer evidence. No projector/ADOT/span/task/log can write payment outcomes or invoke payment routes. Projection role cannot read issuer-only table, mutate business journal/evidence or call authorization endpoints. It may conditionally acknowledge outbox rows; a separately scoped compactor/replay role updates only outbox/capacity metadata, never payment state. Payment response uses authorized journal, NOT history.
Independently expose latest known journal outcome/version when readable, projectedBusinessVersion, criticalSequenceWatermark and missing ranges/producers/tasks; history may lag readable journal. GET detail wrapper includes journalAsOf, projectionAsOf, projectionLagMillis (null if unknown), observation, serverFreshness, client-independent replay cursor and safe gaps. Never mislabel stale projected outcome as current authoritative state. If journal unreadable but projection available, label only LAST_PROJECTED with original asOf/version and unknown authoritative current outcome.
COMPLETE/PARTIAL/UNKNOWN applies as-of manifest+watermark. Critical transition completeness may be complete while task coverage remains partial; UI presents both. COMPLETE requires all required functional observations actually received, not absence of a reported drop; sampled spans do not fill missing tasks. Inferred skipped/not-applicable has explicit provenance.
ServerFreshness CURRENT/STALE/UNKNOWN is observation freshness, not business certainty. Client CONNECTED/DISCONNECTED/UNKNOWN is separate. Known projection backlog/missing watermark => STALE; unmeasurable/read-model outage => UNKNOWN. Never mark current just because HTTP succeeded. Task timing uses original occurred/collected plus causal links; cross-host wall-clock subtraction is not latency truth.

## O2a — canonical event identity preserved
Dedupe key=(environment-bound registered producerId,eventId). ProducerId stable across boots, eventId durable unique/epoch allocation for critical events, original instanceId retained on resend. Best-effort producers must also avoid ID reuse; inability to retain a lost ID implies loss, not reusing it for a different event.
Canonical RFC8785 content keys: schemaVersion,eventId,producerId,instanceId,actor,capability,version,manifestVersion,acquirerRef,merchantRef,terminalRef,transactionId,operationId,attemptId,correlationId,taskExecutionId,taskName,status,occurredAt,producerSequence,provenance,reason,parentTaskId,parentEventId,retryOfAttemptId,originalOperationId,startedAt,endedAt,elapsedMicros,clockQuality,evidenceRef,gapCode. Absent optional values normalize null. Collector/transport fields are outside canonical content; declared wrapper metadata cannot overwrite payload. Reject undeclared fields. Validate context/producer before dedupe; forged context rejects rather than moving events. Same payload/new collector time => exact replay; immutable content change => integrity quarantine. Critical wrapper must match journal/version/outbox hashes. EV1–EV5 retain these original canonical oracles.

## O3 — atomic business journal and critical pending events
Selected direction: required journal/outbox -> DynamoDB Streams -> idempotent projector Lambda -> DynamoDB history -> authorized API/HTML. Technical telemetry independently goes via ADOT/OTel async export. Separate history/telemetry stores are NOT participants in business admission.
For each critical transition, one DynamoDB TransactWriteItems commits the conditional business record/version/head as applicable, normalized verified evidence/receipt where applicable, immutable sanitized outbox row(s) and capacity reservation accounting. Proposed storage split: authoritative business tables and a dedicated critical-outbox table in the SAME account/region; capacity counters live in the outbox table. Use transactional boundary and version conditions; no business-write-then-event dual write, no reliance on Streams record as the only durable event, no transaction including history table. A committed transition cannot exist without its critical outbox record under this contract; transaction failure means neither commits. Ambiguous transaction result is resolved by strongly consistent business/outbox lookup and stable transition token before send; no blindly repeated financial instruction.
Outbox key=(acq,operationId,operationSequence), eventId deterministically allocated from operation+transition token (<=64), immutable canonical event hash. Include journalVersion, state transition kind, original context, source business version/evidenceRef, committedAt, immutable payload. No raw wire/attestation. Duplicate transition/evidence token creates no new business version/outbox event. A receipt/evidence candidate must pass P5/P6/P7/C4 first; then receipt+business version+critical event commit ATOMICALLY, then channel response. History is never awaited. Failed evidence transaction after possible send => conservative NOT_CONFIRMED (or retained readable prior confirmation); no trace-only authority.
CLAIMED_NOT_SENT is business claim + first critical notification, not a separate trace reservation. Original running invocation may proceed by atomic version CAS to POSSIBLE_SEND + critical event before invoking transport. A history/ADOT outage does not interrupt this progression. Retry/restart of an old claim never resumes send; no new payment execution is delegated to a projector/replayer. See O3a/C3.

## O3a — durable states, crash boundaries and failure JSON authority
| State / failure | Required behavior |
| --- | --- |
| unambiguously no claim, required business/outbox transaction fails | no send; current invocation with positive unsent proof C3 503 null NOT_DISPATCHED BUSINESS_ADMISSION_UNAVAILABLE; ambiguous write/unreadable restart null UNAVAILABLE |
| CLAIMED_NOT_SENT after atomic claim/outbox | initial original invocation may CAS/send despite history/telemetry outage; crash-before-CAS retry reads null NOT_DISPATCHED RESERVED_UNSENT, no resumed send |
| POSSIBLE_SEND after atomic CAS/outbox, before invocation | crash is conservatively possible send even if invocation did not occur; restart/duplicate reads NOT_CONFIRMED, never resumes transport |
| P5 evidence+version+outbox commit | known outcome preserved despite history/ADOT failure; channel does not await projection |
| required evidence/outbox transaction unavailable after possible send | C3 current known send ->503 NOT_CONFIRMED/PENDING; unreadable restart ->503 null UNAVAILABLE; readable committed prior confirmation wins |
| history/projector/ADOT/CloudWatch unavailable only | business path continues within reserved outbox capacity; response journal outcome unchanged; observation partial/unknown/stale, no retry/reversal |
No automatic payment SDK/HTTP retry, rollback, reversal or inquiry after possible send. Outbox/projector retry is observation-only. Unlinked request at exact existing 24h window may evaluate a NEW generation with existing warning; linked prior always resolves original, never creates another payment. Retain original links/business journal independent of trace retention.
C3 is the ONE HTTP/JSON precedence authority. No store outage creates an issuer decline. A volatile reply, signed but unadmitted proof, issuer-only table read, history row or sampled span is not a processor-known confirmation. A committed version read earlier in the same invocation can be returned with degraded observation; a prior browser snapshot cannot be asserted by unreadable server restart.

## O5 — finite capacity and durable replay beyond Streams (PROPOSED D3)
Initial A reserves 8 critical slots per new operation in the business transaction BEFORE POSSIBLE_SEND. Atomic per-acquirer counter counts retained rows+reserved future slots, limit 100,000 slots; each event payload <=2048 bytes plus bounded metadata, total row <=4096 bytes, hence logical reserved outbox envelope <=409,600,000 bytes/acquirer excluding DynamoDB/index overhead. No false throughput or cost guarantee. Current A manifest bounds transitions: claim, possible-send, first result, one unknown-to-confirmed late result, first integrity flag (<=5); 8 reserves headroom. Repeats/timers/identical evidence do not create unbounded critical transitions; repeated invalid candidates are bounded diagnostics, not new payment transitions. Future implemented capabilities must supply a proven transition budget/reservation before activation; they cannot consume an A operation's evidence reserve.
Reservation converts future slot to retained row without increasing counter; event ack does not reclaim retained row capacity immediately. Retain allocated slots until a terminal operation's replay-retention checkpoint permits release of unused headroom; UNKNOWN/reserved-unsent keeps future evidence headroom while references remain live. If existing UNKNOWN retains capacity indefinitely, monitor/escalate; never reclaim needed evidence reserve or delete business reference just to admit new work. This conservative capacity cost is explicit.
Warn at 70% and 85% capacity; reject NEW unlinked generations only when reserving 8 would exceed 100,000 (e.g., 99,993+8), or required storage itself fails. C3 503 null NOT_DISPATCHED OUTBOX_CAPACITY when positively unsent, not HISTORY_UNAVAILABLE. Projection/backend outage alone does not immediately block payment; a sufficiently prolonged outage can fill finite retained/reserved capacity and THEN backpressure new work. Already claimed operations have reserved slots for required outcome evidence, not throttled by later new-work saturation. No admission check calls history/ADOT. Previously allocated capacity must be conditional against current counter in same journal transaction; no race-prone count/query-then-write.
Outbox source rows remain durable independent of 24h DynamoDB Streams retention. Pending/unacknowledged/poison rows have NO TTL and are never deleted automatically. Acknowledged rows retained at least seven days from committedAt AND until durable history/projector receipt is confirmed; only then may conditional compaction release retained capacity. Unused terminal reservation may be released only if its future transition is impossible under the manifest, with same conditional accounting and pending rows retained until ack. Keep one first-integrity-flag slot while original references remain eligible and that flag is not yet recorded; do not release future required evidence headroom. This can leave long-lived allocations even after projection recovers, an explicit finite-capacity trade-off requiring monitoring/owner disposition rather than silent reference deletion. Business journal/evidence/idempotency heads/aliases retain existing no-automatic-purge policy.
Proposed asynchronous replay worker queries a context-scoped pending index (eventId,operationId,sequence/committedAt), pages <=100 events / <=1MiB, max1000 events per bounded run with continuation checkpoint. Run every 5 minutes and on authorized recovery request; neither schedule nor endpoint is implemented. Index is eventually consistent: absence is NOT completion; reconcile authoritative per-operation sequence watermark/strong outbox reads and periodic context inventory every 24h. Replay >24h uses source outbox, not expired Streams cursor. Checkpoint advances only after safe ack; failed/late-index pages revisit with overlap+idempotence, never infer exactly-once transport. Stored replay cursors bind service/context; no foreign scans available to user.
A repair worker is allowed only to project notifications. It has no financial invocation rights and cannot CAS CLAIMED_NOT_SENT to POSSIBLE_SEND. Operational source recovery beyond Streams is a new D3 proposal, distinct from forbidden automatic financial recovery.

## O6 — conditional projection, duplicates and poison events (PROPOSED D3)
Streams delivers at least once. Projector accepts only committed critical outbox rows (ignore journal-only change records) or authenticated best-effort task envelopes; validate version/producer/context/schema/hash. Do not source functional truth from arbitrary CloudWatch logs.
Per event, conditional transaction on HISTORY store creates immutable event row/dedupe receipt keyed by producer+eventId and conditionally updates per-operation projection checkpoint/version. Exact replay verifies original hash and is no-op; conflicting same ID quarantines safe metadata and marks observation gap. No overwrite of known newer business projection. Out-of-order sequence N+1 may persist as pending, but contiguous critical watermark does not advance across missing N. Promote pending in order when gap filled; high-watermark is not proof every task observed. Conditional conflict retries only projection transaction.
Only AFTER history event+checkpoint commits durably, acknowledge outbox source conditionally by eventId/hash. Cross-store history+ack is NOT atomic and does not need to be: crash after history commit before ack causes duplicate replay/no-op followed by ack. Crash before history commit leaves source pending. Never ack-before-write. Ack lost/unreadable means keep/replay source. This is safe observation-side dual processing, not dual-write financial evidence. Version/checkpoint conflicts must not remove event or silently skip range.
Transient history outage: partial batch failure returns failed item IDs, bounded retry/backoff; initial proposal max5 retries/max record age1h with bisect-batch and partial failure configuration, alert after60s lag or first failure. Finite Streams age is NOT a loss policy because durable outbox remains. Retry policy values and configured failure destination must be verified in architecture preflight.
Poison schema/hash/untrusted context: after first deterministic failure, persist sanitized quarantine pointer+reason (eventId/context/hash, <=1KiB, not raw stream payload), mark gap in authorized diagnostics, isolate from healthy records and stop hot looping. Do not falsely ack as successfully projected. Proposed failure-destination S3 restricted metadata pointer with seven-day minimum plus pending source retained until resolved; native AWS failure destinations may contain full stream records, so implementation must explicitly validate redaction/IAM/retention or use sanitized pointer path instead. Failure to write quarantine/notification does not delete source; alert may itself be unavailable, later reconciliation must discover pending source. Authorized operator may repair schema mapping and replay original through projector, never alter signed business outcome or invent missing tasks. Permanent skip only by separately approved disposition with visible gap; no implicit poison deletion. This proposal adds storage/permissions that require D3/Security approval.
A record replayed after history seven-day retention is not resurrected as fresh history: retain committedAt/collectedAt, suppress expired content, record expiry acknowledgement/watermark only after authorized retention validation. Distinguish expired from poison/missing; no business evidence or links purged. Do not promise recovery of best-effort events never written durably.

## O4 — D3 UI, access, privacy, retention and telemetry proposal
Read API remains authorized 1-second active polling rather than SSE/WebSocket initially. GET list/detail/events never dispatch payment. Default/max page100, replay bounded1000 events or1MiB; >bound or expired15-minute signed subject/context/filter/watermark cursor =>410 RESYNC_REQUIRED with paged snapshot and visible gap; tampered cursor400. Reauthorize every page; list/context index acq+mid sorted firstReceipt+transactionId; detail partition acq+mid+transactionId, sort sequence/eventId. No global tenant scan, no direct browser CloudWatch/DynamoDB credentials. Pending projection sequence IDs and index schema details remain proposed implementation, not deployed behavior.
Submit needs console:submit+active full context; list/detail/poll/replay console:read+same context. Issuer diagnostic additionally diagnostics:issuer; processor/projector cannot read issuer-only truth as confirmation. Revocation/context switch cancels requests/clears stale-context view and server denies next request. Already seen data cannot be remotely recalled. Encrypt transport/storage, role-scoped IAM, restricted internal replay/quarantine; independent Security review required.
Functional history retains seven days from original collectedAt (critical=committedAt, task=initial authorized collection), never from replay/projectedAt. Filter at logical expiry even if TTL physical deletion lags; proposed physical deletion target<=48h and alert on lag. Delete history/index/dedupe content consistently but not business journal/evidence/original links/aliases. Pending source/quarantine retention above may exceed UI retention for recovery; metadata only, restricted backend, no raw exports. Dedupe/checkpoint metadata used beyond UI expiry must not re-expose expired payload. Trace expiry is not duplicate window or business retention.
Freshness PROPOSED, measurable not guaranteed by AWS documentation: for healthy source/projector/read API and connected reader at100 active transactions/1000 events, critical committedAt→projectedAt p95<=2s/p99<=5s; projectedAt→display p95<=2s/p99<=5s. Thus end-to-end proposed p95<=4s/p99<=10s must be measured directly (percentiles do not algebraically prove the combined percentile). For best-effort tasks measure only successfully collected events; report drops/coverage separately, never hide them in latency. Reconnect to an ALREADY PROJECTED bounded1000-event snapshot <=10s; source-backlog drain is separate measured recovery metric, no unconditional10s promise after prolonged outage. Show backlog age/critical watermark gaps. Poll backoff5/10/30s and offline state affect freshness but never repeat POST.
ADOT layer/collector exports asynchronously to configured AWS telemetry backends. Java25 Lambda runtime/architecture and exact ADOT layer/agent/collector compatibility, lifecycle flush/drop policy, sampled rate/export queue/limits, memory overhead and Lambda scheduling MUST be preflighted before construction approval; no layer ARN/version selected, installation or tested compatibility claimed. Sampling may reduce technical telemetry costs but not critical event admission.
CloudWatch Logs subscription alternative is best-effort diagnostic transport (research documents usual under-three-minutes delivery, retries up to24h and possible losses); it cannot substantiate seconds-level UI targets. Do not switch functional projection to that path while retaining these freshness proposals without new measured/reviewed contract. No backend availability or sampled span determines payment outcome.
