## Harness contract

Use synthetic fixtures only. For each run record scenario ID, capability/operation, authorized subject and acquirer/merchant/terminal, deterministic fixture/seed, injected actor/failure point, transaction/operation/attempt/task/event references, processor-visible result and separately permitted simulator-internal evidence. Observe API/UI, persisted sanitized events and business journal independently. Fix the approved channel/ISO profile revision and request/response vectors for adaptation tests. Fault injection is operator-controlled, not a request-body privilege. Do not add a public late-evidence endpoint merely to run tests: use a separately authorized existing test seam. Each Then requires observable evidence; screenshots alone do not prove persistence, authorization or non-dispatch.

Success, rejection, timeout/unknown, duplicate submissions/events, malformed and invalid references, reattempt, late evidence and reconnect are covered. A new purchase after the existing idempotency generation/window must follow current A rules, not a newly invented console policy.

Not applicable to this commissioned business slice: reversal original-reference eligibility/partial amounts/acknowledgment loss, Operation C network inquiry, automatic reversal, stand-in, capture, refunds and CNP/3DS challenge paths. These require separately commissioned capabilities/profiles. OBS-12 covers current invalid correlation/reference behavior, not a claimed reversal endpoint. Console history lookup never supplies issuer confirmation unavailable to the processor. OBS-27 is a contract acceptance obligation for future implemented work, not a request to build it now.
