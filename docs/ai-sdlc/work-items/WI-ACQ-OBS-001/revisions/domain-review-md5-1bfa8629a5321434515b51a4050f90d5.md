## Findings and exact corrections

### M1 — MEDIUM: subscription retry identity/conflict semantics are incomplete

Affected gate: WebSocket protocol construction; does not prevent selecting exposure or retention policy.

O5 defines requestId and client subscriptionId, then says duplicate “subscribe token” returns the same active generation. It never specifies which field is that token, its connection/session scope, or the response when reused with a different transaction in the same acquirer/merchant context. Context change/new connection gets a new generation, but changing transaction with reused identifiers in the same context is not defined. A lost ACK followed by retry must not silently redirect a subscription or apply an old ACK/frame to a different transaction.

Correction: specify the idempotency identity (for example connection/session binding plus requestId), immutable tuple including subscriptionId/environment/context/transaction, and conflict rejection for changed tuple. Define whether replacing a subscription requires a fresh request/subscription ID and always a fresh generation. Require ACK and pre-ACK buffer matching to the pending request/transaction, then generation filtering; no pre-ACK frame is rendered before that binding is established. State safe lost-ACK/repeated-ACK behavior and removal/lease behavior without invoking payment.

Add fixed W cases for identical subscribe retry after lost ACK, same requestId with changed transaction, same subscriptionId concurrently reused for another transaction, old ACK after reauthentication/new generation, and no automatic POST in every branch. The owner need not design these fields.

### M2 — MEDIUM: diagram still admits a misleading WebSocket prerequisite and two head meanings

Affected gate: activity documentation/construction handoff.

The revised source diagram is substantially corrected: actual transaction ID, atomic predispatch states, single invocation, retention/gap branch and best-effort/ADOT separation are visible. However START -> AUTH -> OPEN -> SUBMIT has no OPEN failure branch, so it can be read as making an operational socket prerequisite for payment. O3/C3 explicitly permit HTTP payment while WebSocket/notifier is down.

Also ACK says “fixed source head” and queries up to that head, while O6/W01 permit a fresh snapshot H >= ACK head. W01 deliberately ACKs head2 and queries H3. Both protocols could be safe, but the same diagram must not call these different heads the same fixed value.

Correction: label OPEN as a best-effort/parallel transport attempt and show disconnected/WS-failure progression to explicit HTTP submission when HTTP JWT/service checks remain valid, with observation degraded. Authentication failure still blocks unauthorized submission. Label ACK head as routing-installed observed head, then label strong snapshot acquisition H >= ACK head, fixed for that snapshot's pages. Define SEND explicitly as one financial downstream invocation for the claimed operation, not per task/event/notification. Preserve the current no-resend and retained catch-up edges.

Update the coordinator-owned .md/.mmd together and then synchronize the PNG/Drive revision; older visual artifacts cannot substantiate the corrected flow. I did not edit these files. Decision-proposal's obsolete diagram-hash/correction receipt should be refreshed at the same handoff.

### L1 — LOW: W25 illustrative JWT times are not valid JWT claim encodings

Affected gate: authentication fixture/preflight clarity, not owner boundary selection.

W25 claimFixtures names iat/exp as ISO timestamp strings. Actual JWT iat/exp use NumericDate numeric values; these examples are explicitly not real signed JWTs, but should not become future token-validator acceptance inputs unchanged.

Correction: use numeric epoch-second claims for the exact stated times and retain separate readable timestamp annotations, or rename the strings as illustrative decoded time descriptions outside a JWT claims object. Keep the expiry=min(JWTexp,lease) oracle, existing issuer audience/subject checks and no expired-token fallback. This does not require a real token, secret or crypto test now.
